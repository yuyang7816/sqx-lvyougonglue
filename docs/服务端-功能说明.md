# 服务端功能说明

服务端没有给游客点的页面。它是一直开着的程序：用户端和管理端把「登录、看攻略、进群、付款」这些请求发给它，它检查是否允许、把结果存进数据库，必要时再去问微信、支付宝、短信这些外面的服务。

可以把它理解成总台。两个前台（用户端、管理端）说的话，都由总台记账，并在需要时给外面的公司打电话。

数据库配置在 `server/sqx-application/src/main/resources/`。本机常用 `application-dev.yml`，库名是 `lvyougonglve`。目的地、景点、路线、群聊、动态、订单都记在这里。

启动类是 `com.sqx.SqxApplication`。端口是 **9097**，所有接口都在 `/sqx_fast` 下面。接口列表在：

http://127.0.0.1:9097/sqx_fast/doc.html

Redis 写在配置里。当前 `sqx.redis.open` 默认是关的，所以它不是必须先启动的依赖。如果以后把开关打开，就要先启动 Redis。

下面先说它为两个前台做哪些事，再说它会主动连接哪些外面的服务。

## 它为用户端做的事

这些都是用户在手机里点一下之后，由服务端完成的：

- **注册和登录**：检查手机号和短信验证码，或检查密码。通过后发给用户一张登录凭证。
- **首页内容**：返回目的地、景点、路线、演唱会、玩乐租赁等内容列表和详情。
- **搜索**：按关键词检索内容，并记下搜索历史。
- **攻略群**：创建群、加入群、群成员管理、群相关信息查询。
- **消息与聊天**：保存会话和消息；用户端再用网页套接字收实时消息。
- **动态社交**：发布动态、点赞、评论、收藏、关注、黑名单、投诉。
- **钱包与提现**：余额、明细、提现申请。提现只生成待审核记录，不会在这一步把钱转到对方支付宝。
- **邀请分销**：记录邀请关系，供「我的团队」「我的收益」显示。
- **实名认证、注销申请**：保存用户提交的资料，交给管理端处理。
- **帮助、反馈、协议、关于我们**：把后台写好的文章发给用户端。
- **支付回调**：接收微信、支付宝通知，更新订单和资金状态。

## 它为管理端做的事

- 工作人员登录，并按角色限制能看的菜单。
- 提供数据中心要用的统计数字。
- 用户列表、用户详情、注销处理。
- 目的地 / 国家地区、景点、旅游产品、路线相关内容维护。
- 动态、评论、店铺、轮播、素材、消息与投诉处理。
- 订单中心、财务、VIP / 优惠券、分销配置。
- 管理员、角色、菜单等系统能力。
- 保存系统配置。用户端下次请求时读到新的短信、支付和图片存储配置。

## 对接了哪些外面的服务

下面每一项都是服务端真的会向外发送请求的。密钥没填时，它不会假装成功，用户端会看到失败提示。

### 短信

注册、验证码登录、找回密码等，由服务端发短信。可对接短信宝、阿里云短信、腾讯云短信等，具体以管理端系统配置为准。

### 支付

微信支付、支付宝。密钥和回调地址要自己申请并配置。

### 图片存储

上传头像、内容图片、认证材料等。可存本机或对象存储（如阿里云 OSS），以系统配置为准。

### 地图

部分管理端选点、定位会用到腾讯地图等地图服务，密钥要自己申请。

## 和两个前台的关系

- 用户端只负责展示和采集操作，真正记账在服务端。
- 管理端改完内容或配置后，用户端下次请求才会看到新结果。
- 三端必须连同一个库、同一个服务端实例，数据才会一致。
